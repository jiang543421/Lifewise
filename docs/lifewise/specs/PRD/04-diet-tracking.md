## 1. 产品目标（SMART）

| 维度 | 描述 |
|---|---|
| **Specific** | 让用户在 30 秒内完成一顿饭的记录，看到每日 / 每周热量与营养结构 |
| **Measurable** | 单餐记录 P95 < 1.5s；连续 7 天记录用户占比 ≥ 35% |
| **Achievable** | 复用现有账号与 PostgreSQL；食物库 200+ 条目内置；卡路里聚合纯 SQL |
| **Relevant** | 饮食是个人健康基础数据；与任务（运动打卡）、消费（餐饮开销）天然关联 |
| **Time-bound** | MVP 在 Phase 1（4-6 周）交付；AI 饮食建议、图片识别放入 v1.1+ |

**核心 OKR**：
- **O1**：让用户「看见自己吃了什么、结构合不合理」
- **KR1.1**：注册用户 7 天内记录至少 5 餐的比例 ≥ 40%
- **KR1.2**：用户每周查看「本周营养汇总」页的比例 ≥ 30%
- **KR1.3**：食物库条目被复用率（选食物库 / 手动输入）≥ 70%

## 2. 用户画像

### 用户画像 A：减脂期用户「小米」

- **角色**：25-35 岁健身 / 减脂人群
- **痛点**：在用薄荷健康 / MyFitnessPal，但数据在国内服务器，担心隐私；想要更轻量的工具
- **核心任务**：
  1. 早餐拍照或输入查卡路里
  2. 看到今天还剩多少热量额度
  3. 一周看营养素比例是否合理

### 用户画像 B：慢病管理「老周」

- **角色**：45-65 岁糖尿病 / 高血压人群
- **痛点**：医生要求控制碳水与钠摄入；手动记录繁琐
- **核心任务**：
  1. 每餐记录主要食物
  2. 看到今日碳水是否超标
  3. 月度复盘给医生看记录

### 用户画像 C：精致妈妈「小雅」

- **角色**：28-38 岁关注家人营养的妈妈
- **痛点**：想记录孩子辅食结构；想看到家庭饮食是否均衡
- **核心任务**：
  1. 早餐记录孩子吃了什么
  2. 周末看家庭营养结构
  3. AI 建议下周菜谱调整

## 3. 功能清单

### MVP（v1.0）— Phase 1

#### 餐次核心

- [ ] MEAL-001 新增餐次（早 / 午 / 晚 / 加餐，类型必填）
- [ ] MEAL-002 编辑 / 软删除餐次（30 天回收站）
- [ ] MEAL-003 餐次下添加食物条目（食物库选 / 手动输入）
- [ ] MEAL-004 食物份数（servings，1 = 1 份 / 100g）
- [ ] MEAL-005 餐次时间（默认当前，可调整到 ±12h）
- [ ] MEAL-006 餐次备注（≤ 200 字）

- [ ] MEAL-011 食物库搜索（按名称 / 分类）
- [ ] MEAL-012 用户自定义食物（增删改，私有）
- [ ] MEAL-013 食物分类筛选（主食 / 肉类 / 蔬菜 / 水果 / 饮品 / 零食）

#### 营养统计

- [ ] MEAL-020 餐次卡路里合计（自动计算）
- [ ] MEAL-021 今日 / 本周热量趋势折线
- [ ] MEAL-022 本周宏量营养素饼图（蛋白/碳水/脂肪占比）
- [ ] MEAL-023 单餐营养详情卡
- [ ] MEAL-024 每日推荐摄入估算（按体重 / 性别 / 活动量配置）

#### 数据导出

- [ ] MEAL-030 月度饮食记录导出 CSV
- [ ] MEAL-031 月度营养汇总 PDF（医生复盘用）

### 扩展（v1.1+）— Phase 2 及以后

#### AI 能力（v1.1）

- [ ] MEAL-101 AI 饮食建议（基于本周宏量营养素缺口推荐食物）

#### 多模态（v1.2）

## 4. KANO + RICE 划分逻辑

### KANO 模型归类

| 需求 | KANO 类别 | 理由 |
|---|---|---|
| 餐次 CRUD、食物库、营养统计 | **基本型（MUST）** | 饮食记录 App 的存在基础 |
| 月度营养汇总、自定义食物 | **期望型（SHOULD）** | 显著差异化，但 MVP 可缺 |
| AI 饮食建议 | **魅力型（COULD）** | 用了惊喜，但纯统计也能给基础洞察 |
| 拍照 / 语音 / 条形码 | **无差异型（WON'T）** | 当前阶段与本地 LLM 弱相关，依赖视觉模型基建 |

### RICE 评分

| 需求 | Reach | Impact | Confidence | Effort | RICE | 决策 |
|---|---|---|---|---|---|---|
| 200+ 食物库 | 1.0 | 3 | 1.0 | 1 | 3.0 | **进 MVP**（种子数据集） |
| 今日/本周热量趋势 | 0.8 | 2 | 1.0 | 0.5 | 3.2 | **进 MVP**（零成本 SQL 聚合） |
| 宏量营养素饼图 | 0.6 | 2 | 0.9 | 0.5 | 2.16 | **进 MVP**（视觉化驱动留存） |
| 自定义食物 | 0.5 | 2 | 0.9 | 0.5 | 1.8 | **进 MVP** |
| 推荐摄入估算 | 0.4 | 1 | 0.7 | 0.5 | 0.56 | **进 MVP**（输入一次，持续受益） |
| 月度 PDF 报告 | 0.2 | 2 | 0.6 | 4 | 0.06 | **v1.1**（慢病管理用户比例低） |
| AI 饮食建议 | 0.4 | 3 | 0.5 | 6 | 0.10 | **v1.1**（置信度低） |
| 拍照识别 | 0.3 | 3 | 0.3 | 16 | 0.017 | **v1.2**（视觉模型成本高） |

**结论**：MVP 收纳 MUST + 食物库 + 趋势/饼图（用户感知最强的功能）；拍照识别等视觉能力延后到 v1.2。

## 5. 用户故事

### US-MEAL-01：30 秒记录一顿饭

> 作为**减脂期用户小米**，我需要**在吃早餐时 30 秒内记下吃了什么**，以便于**不破坏早晨节奏**。

**验收标准（AC）**：
- **AC-1**：从首页点「+ 餐次」到看到餐次卡片出现在今日列表，端到端 P95 < 1.5s
- **AC-2**：从食物库选食物时支持拼音首字母搜索（输入「jf」可定位「鸡饭」）
- **AC-3**：未选食物时只填「备注 + 卡路里」也能保存（懒人模式）

### US-MEAL-02：本周热量趋势

> 作为**减脂期用户小米**，我需要**看到本周每日热量折线**，以便于**判断是否需要调整饮食节奏**。

**验收标准（AC）**：
- **AC-1**：本周汇总页顶部展示 7 天热量柱状图，每日柱体上标注当日总 kcal
- **AC-2**：折线同时叠加「推荐摄入」参考线，超出区间高亮
- **AC-3**：点击某天跳转该天全部餐次列表

### US-MEAL-03：营养素比例看是否合理

> 作为**慢病管理老周**，我需要**看到本周蛋白/碳水/脂肪的占比饼图**，以便于**控制碳水不要太多**。

**验收标准（AC）**：
- **AC-1**：营养汇总页饼图三色展示本周宏量营养素占比
- **AC-2**：饼图下方标注「推荐区间」参考（如「碳水 45-65%」），偏离区间提示
- **AC-3**：营养汇总数据来自本周餐次聚合，统计耗时 < 500ms

### US-MEAL-04：自定义食物

> 作为**精致妈妈小雅**，我需要**添加孩子常吃的辅食如「南瓜小米糊」**，以便于**不用每次手动输入**。

**验收标准（AC）**：
- **AC-1**：食物库页可「+ 自定义食物」，填名称、分类、每 100g 卡路里与三大营养素
- **AC-2**：自定义食物在搜索结果中以「我的食物」标签标识
- **AC-3**：删除自定义食物时关联的 meal_item 不会物理删除，meal_item.food_id 置 NULL 显示「已删除」

## 6. 功能范围与边界

### In Scope（MVP）

- 餐次 CRUD（早/午/晚/加餐）+ 食物条目
- 内置 200+ 食物库 + 用户自定义食物
- 餐次卡路里自动计算（基于食物库）
- 今日/本周热量趋势、宏量营养素饼图
- 推荐摄入估算（输入身高/体重/活动量）
- 月度 CSV 导出

### Out of Scope（明确不做）

- **不做**：拍照识别食物（v1.2）
- **不做**：语音录入（v1.2）
- **不做**：AI 饮食建议（v1.1）
- **不做**：条形码扫描（v1.2）
- **不做**：家庭成员档案（v1.3）
- **不做**：与运动 App（Apple Health / 微信运动）联动
- **不做**：月度 PDF 报告（v1.1）

## 8. 风险与应对

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| **食物库数据准确度争议（同样食物不同来源差异大）** | 中 | 高 | 标注数据来源（如「中国食物成分表第 6 版」），允许用户覆盖；UI 显示「估算」字样 |
| **用户跳过食物库直接输入文本，卡路里留空** | 中 | 高 | 懒人模式：纯文本 + 卡路里手动输入；营养饼图无数据时显示「数据不足」 |
| **食物库分类体系用户认知不同（南方人/北方人差异）** | 中 | 中 | 分类保留英文 + 中文别名，搜索做归一化 |
| **碳水/蛋白/脂肪单位搞错（g vs mg）** | 中 | 中 | 录入 UI 强校验单位；展示时统一 g |
| **饮食数据长期膨胀（一年几千餐）** | 中 | 中 | 按月分区；超过 1 年自动归档（仍可读，不进活跃统计） |

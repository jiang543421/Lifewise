## 0. 设计目标与范围

### 0.1 目标

基于 MVP PRD(消费 CRUD + 8 默认分类 + 月度统计 + 月度预算 + 超额预警 + CSV 导出),交付**单文件 HTML UI 原型**,用于:

- **设计契约**:产品、设计、研发、测试的视觉与交互共识
- **用户路径演示**:让 stakeholder 在浏览器走完所有核心流程
- **工程参考**:为后续前端实现提供布局、组件、交互的设计基准

### 0.2 交付范围(In Scope)

- **9 个视图**(V1-V9,详见 §1.2)
- **8 个核心交互流**(F1-F8,详见 §5)
- 移动优先 + 响应式(平板/桌面,详见 §7.1)
- **12+1 个 expense 专属组件** + 8 个全局复用组件(详见 §3.2 / §3.3 / §3.4)
- **8 个 expense token + 8+4 分类色板 token**(详见 §4.2 / §4.3)
- **3 套状态机显式标注**:录入 5 态(含 draft) / 数据 5 态(含 stale) / 预算 4 态(含 unset)(详见 §6)
- 中保真 + 伪交互(本地 JS 模拟状态切换)

### 0.3 不在范围(Out of Scope)

- 后端 API(原型使用本地 JS)
- 真实 Web Push(用「静音本月」开关模拟 + 通知中心降级展示)
- 真实图表库(用 SVG/CSS 手绘,不用 chart.js)
- CSV 智能导入 / AI 异常检测(PRD v1.1+)
- OCR 小票 / 多账户 / 家庭账本(PRD v1.2+)
- 周期性账单 / 实时汇率(PRD v1.3+)

## 1. 信息架构(IA)

### 1.1 顶层结构

```
App 入口
 └─ V1 今日 Dashboard(默认首屏,沿用 02-daily-ui V1)
      ├─ [💰 今日支出卡 · Top-1 主卡]      ──→ V2 Sheet(支出)
      ├─ [📊 本月统计卡 · 次卡]             ──→ V5 月度统计
      └─ [🎯 预算进度卡 · 条件卡]           ──→ V6 预算管理
 └─ 👤 我的 → 消费明细(二级入口)
      └─ V3 消费列表
           ├─ 顶部 V8 搜索/筛选入口
           ├─ 单条 → V4 详情
           └─ FAB 单击 → V2 Sheet(默认支出)
 └─ V2 录入 Sheet(从 V1/V3 FAB 唤起,底部 70% 屏)
      └─ Type Segmented 切换:支出 / 收入
           ├─ 支出 → 8 默认分类 + 自定义
           └─ 收入 → 4 收入分类(工资/退款/转账收入/其他)
 └─ V5 月度统计
      └─ 顶部 ExpJournalCard(1/3 手帐元素) ──→ V7 月度复盘 Sheet(底部 80% 屏)
 └─ V6 预算管理
      ├─ 总预算 ExpBudgetProgress
      ├─ 分类预算列表
      └─ 设置入口 → V9 设置(分类管理 / 通知开关 / 预算周期说明)
 └─ 全局通知中心(沿用 02-daily-ui G3)—— Push 降级,与 V9 通知开关正交
```

### 1.3 V1 Dashboard 新增 3 张卡的内容

| 卡 | 视觉 | 优先级 | 点击行为 |
|---|---|---|---|
| **💰 今日支出**(主卡,Top-1) | 大字 `¥128.50` + 「今日已记 5 笔」+ 副标「点击记一笔」 | 永远显示 | 唤起 V2 Sheet,**Type=支出** |
| **📊 本月统计**(次卡) | 中字 `¥3,256 / ¥5,000` 进度条 + 「预算 65%」 | 永远显示 | 跳 V6(已设预算) / 跳 V9(未设) |
| **🎯 预算进度**(条件卡) | 仅当本月某分类 ≥ 80% 时显示;红/黄徽标 | 条件显示 | 跳 V6 |

**优先级逻辑**:💰 卡永远显示(无数据时占位「今日还没记 → 点击记一笔」);📊 始终显示;🎯 条件显示。

### 1.4 Tab Bar / 导航策略

- **底部 Tab Bar 保持 5 项不变**(🏠📋🎯📝👤),与 daily-ui 对齐
- **expense 模块不进入 Tab**,但 👤 我的页 → "消费明细" 是 1 个二级入口
- **V3 列表页内有自己的 Tab**:类型 Segmented Control(第 1 行)与时间 Chip(第 2 行)分两层
- **V5 / V6 内部没有 Tab**,单页直出

### 1.5 IA 否定备选

| 备选 | 否定理由 |
|---|---|
| 把 expense 塞进 6 Tab | 5 Tab 已占满;移动端 Tab 6 项文字挤压 |
| 在 V1 Dashboard 内嵌整个消费模块 | 与已有 📝 日报卡重复模式;V1 已重,再叠消费 V2 V3 信息密度爆 |
| V3 列表与 V5 统计合并 | 用户场景不同:记账日常用 V3;月度复盘用 V5,合并后月度视图被日常列表淹没 |

## 5. 交互流(8 个核心流)

### F1 · 10 秒快速支出录入(V2 Sheet 路径)

| 字段 | 内容 |
|---|---|
| **触发点** | V1 Dashboard 💰 卡 / V3 列表 FAB 单击 / 👤 我的 → 消费明细 → [+] |
| **步骤** | ① 单击 FAB(0ms)→ ② Sheet 70% 滑入(300ms)+ 金额输入自动获焦 → ③ 数字键盘输入金额(如 `35.5`)+ 默认「支出」Type → ④ 点选分类网格(「餐饮」)(150ms)→ ⑤ 点 [保存](50ms)→ ⑥ 关闭 Sheet + Toast「已记 ¥35.5 餐饮 ✓」(300ms) |
| **端到端** | < 800ms(满足 PRD P95 ≤ 1.0s) |
| **状态/反馈** | Sheet 滑入:`type=支出` 默认;金额框:空=占位「0.00」/ 输入中=主色 / 合法=主色 / 超 2 位小数=红色抖动;分类:8 网格 3×3,第 9 格「+」= 自定义;保存中:按钮变「保存中…」+ 旋转图标;保存成功:Sheet 滑出 + Toast「已记 ¥35.5 餐饮 ✓」+ 30s 撤销 |
| **边缘场景** | (a) 金额空 → 按钮置灰;(b) 金额 ≤ 0 → Toast「金额必须 > 0」+ 输入框抖动;(c) 未选分类 → 按钮置灰 + 提示「选个分类」;(d) 保存失败 → Toast「保存失败 ⟲ 重试」+ 草稿保留在 Sheet 内 |

### F2 · 2 秒极简支出录入(FAB 长按快捷金额)

| 字段 | 内容 |
|---|---|
| **触发点** | V1 / V3 FAB **长按 500ms** |
| **步骤** | ① 长按 FAB 0-500ms → ② 脉冲环扩大(linear 500ms)→ ③ 500ms 触发 FAB 缩放 1.0→1.15→1.0(200ms 弹性)+ 4 宫格菜单(¥10/20/50/100)径向弹出 → ④ 点选某金额 → ⑤ 直接写入(`category=last_used_category` 来自 localStorage,`type=支出`)→ ⑥ Toast「已记 ¥10 餐饮」+ 30s 撤销 |
| **端到端** | < 600ms |
| **状态/反馈** | **3 时序动效**详见 §6.2.4;4 宫格菜单半径 60px 包围 FAB;点击外侧 = 取消;提前释放 = 脉冲环收缩 + FAB 缩放回 1.0(150ms ease-in) |
| **边缘场景** | (a) 首次使用无 `last_used_category` → **直接记「其他」分类**(不走 Sheet,保持极简)+ Toast「下次将记住你的选择」+ 提示推动用户用一次完整录入建立习惯;(b) `last_used_category` 已被删除 → fallback「其他」+ 静默清理 localStorage |

## 6. 状态机(3 套显式)

### 6.1 录入状态机(F1/F2/F3 共用,5 态含 draft)

```
(idle) idle
   │ 用户点 FAB / 打开 V2 Sheet
   ▼
(editing) editing
   ├─ 金额/分类/备注写入 → 防抖 500ms 写入 localStorage draft_expense(24h 有效)
   │
   │ 触发关闭路径(ESC / 点遮罩 / 浏览器关闭):
   │   ├─ 草稿为空 → 直接关闭
   │   └─ 草稿非空 → 弹 Dialog「放弃这笔记录?」[放弃] [保留并继续编辑]
   │       └─ [保留] → Sheet 重新打开,字段恢复
   │ 浏览器关闭(beforeunload)→ localStorage draft_expense 已存,下次打开 V2 自动恢复
   │
   │ 点 [保存] / 键盘「完成」/ 长按 FAB 选金额(F2 跳过此态)
   ▼
(saving) saving  ← 按钮「保存中…」+ 旋转图标
   │
   ├── 成功 ──► (成功) saved  关闭 Sheet + Toast「已记 ¥X XXX ✓」(30s 撤销 = 删除) + V3 新增项置顶高亮 1.5s
   │
   ├── 失败 ──► (失败) failed  Toast「保存失败 ⟲ 重试」+ Sheet 内草稿保留 + 按钮恢复「保存」
   │
   └── 409 冲突(原型不模拟) ──► (冲突) conflict  阻塞关闭,Dialog「请解决冲突」
```

| 状态 | UI 元素状态 | 触发 | 反馈 |
|---|---|---|---|
| `idle` | Sheet 未打开 / 金额框空 | F2 长按直接跳过此态 | 按钮「保存」置灰 |
| `editing` | 金额框获焦 + 数字键盘弹出 | 输入金额 / 选分类 | 按钮激活条件:金额 > 0 + 分类已选 |
| `draft`(editing 子态) | 同 editing 视觉 | 任何字段变化后 500ms 防抖 | localStorage 静默写入,无 UI 反馈 |
| `saving` | 按钮变「保存中…」+ 旋转 | 点保存 | 防重入:按钮置灰 |
| `saved` | Sheet 滑出 + Toast | API 200 | 30s 撤销(对 F2:撤销后该笔消失) |
| `failed` | 按钮恢复「保存」+ 红色描边 200ms | API 500/网络 | Toast 红色「⟲ 重试」 |

### 6.2 数据加载状态机(V3/V5/V6/V8 共用,5 态含 stale)

```
(empty) empty
   │ 视图挂载 / 筛选变化 / 月份切换
   ▼
(loading) loading  ← Skeleton(对应视图布局)100ms 起
   │
   ├── 数据返回 ──► (成功) success
   │                  ├─ 有数据 ──► 渲染列表/图表
   │                  └─ 0 数据 ──► 切回 empty 状态(无 loading 闪)
   │
   ├── 切月份中(用户触发)──► (stale) stale  旧数据保留 + 顶部 8px loading 指示条
   │                            │
   │                            ├── 新数据返回 ──► success(替换)
   │                            └── 失败 ──► error(旧数据保留 + Toast 重试)
   │
   └── 错误 ──► (失败) error
                ├─ 网络错误 ──► 插画 + Toast「加载失败 ⟲ 重试」+ [重试] CTA
                └─ 服务端 5xx ──► 同上
                重试 → 回 loading
```

| 状态 | 触发 | 视觉 |
|---|---|---|
| `empty` | 数据 0 条 / 筛选 0 命中 | 插画 + 场景化文案 + 主 CTA |
| `loading` | 视图挂载 / 筛选 | Skeleton 灰块 100ms 起 |
| `stale` | 切月份中(V3/V5) | **旧数据保留 + 顶部 8px loading 指示条**(不遮罩,避免闪烁) |
| `success` | API 200 | 正常渲染 |
| `error` | 网络/5xx | 插画 + 错误文案 + [重试] 按钮;**保留 URL 与上次筛选**,重试复用 |

### 6.3 预算执行状态机(F6 + V6 主轴,4 态含 unset)

```
(unset) unset   未设预算
   │ 用户在 V6 / V9 设预算
   ▼
(healthy) healthy   progress < 80%
   │ 某笔支出后,重算
   ▼
(warning) warning   80% ≤ progress < 100%
   │ 触发条件:某分类进度首次跨过 80% 阈值
   ├─ Web Push(若 V9 通知开关 ON)=「⚠️ 本月餐饮预算已用 82%」
   ├─ V1 Dashboard 🎯 卡出现(条件卡,黄)
   └─ V6 进度条变黄 + 文案「临近」
   │
   ▼
(over) over      progress ≥ 100%
   │ 触发条件:某分类进度首次跨过 100% 阈值
   ├─ Web Push(若 V9 通知开关 ON)=「🚨 本月餐饮预算已超支」
   ├─ V1 🎯 卡变红 + V6 弹 ExpJournalAlertDialog(2/3 手帐元素)
   ├─ 「静音本月」开关 = 关闭后本月不再推送,但 V6 进度条仍红
   └─ 月初 0:00 自动重置(下月重新计)
```

| 状态 | 颜色 | 文案 | Web Push | V1 卡片 | V6 弹窗 |
|---|---|---|---|---|---|
| `unset` 未设 | `--expense-neutral` 灰(无进度条) | "还没设预算,设一个帮你控制开支" + [设预算] CTA | 不发 | 🎯 卡隐藏 | 展示 [设预算] CTA |
| `healthy` `< 80%` | `--success` 绿 | "健康" | 不发 | 隐藏 🎯 卡 | 无 |
| `warning` `80-100%` | `--warning` 黄 | "临近" | 首次跨阈值 1 次 | 🎯 卡显示(黄) | 无 |
| `over` `≥ 100%` | `--expense-expense` 红 | "已超额 ¥X" | 首次跨阈值 1 次 | 🎯 卡显示(红) | ExpJournalAlertDialog 弹 1 次(可静音) |

**关键约束**:
- 同一分类**每月最多 1 次临近 Push + 1 次超额 Push**(对齐 PRD §8 风险 #4 应对)
- 静音开关仅作用本月,下月自动失效(localStorage key:`expense_mute_2026-07`)
- 删除自定义分类 → 该分类预算归 0 → 状态自动回 `healthy`
- 预算编辑后立即重算,无防抖

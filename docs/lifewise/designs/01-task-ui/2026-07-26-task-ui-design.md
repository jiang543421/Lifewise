## 0. 设计目标与范围

### 0.1 目标

基于 MVP PRD(任务 CRUD + 习惯打卡),交付**单文件 HTML UI 原型**,用于:

- 设计契约:产品、设计、研发、测试的视觉与交互共识
- 用户路径演示:让 stakeholder 在浏览器走完所有核心流程

- 14 个视图(详见 §2)

- 中保真 + 伪交互(本地 JS 模拟状态切换)

- 智能能力(AI 排期 / 标题改写,v1.1+)

- 番茄钟 / 日历双向同步(v1.3+)

## 1. 信息架构(IA)

### 1.1 顶层结构

```
App 入口
  └─ 今日 Dashboard(默认首屏)
       ├─ 「任务」入口 → 任务模块
       │    ├─ 列表视图(今日 / 本周 / 全部 Tab)
       │    ├─ 看板视图(状态 × 优先级)
       │    ├─ 搜索页
       │    ├─ 任务详情页(含子任务)
       │    ├─ 新建/编辑任务(底部弹层)
       │    └─ 回收站
       └─ 「习惯」入口 → 习惯模块
            ├─ 习惯列表(含 streak)
            ├─ 习惯详情 + 补卡页
            └─ 新建/编辑习惯(底部弹层)
  └─ 全局设置(Web Push 开关、时区、回收站清理提醒)
  └─ 全局通知中心(Push 降级)
```

### 1.2 导航规则

- **底部 Tab Bar**:`🏠 今日` / `📋 任务` / `🎯 习惯` / `👤 我`
  - 「今日」= Dashboard(总览)
  - 「任务」「习惯」= 单模块全部页的二级入口
  - 「我」= 设置、回收站入口
- **顶部 AppHeader**:左侧返回/标题,右侧上下文操作
- **FAB(浮动 + 按钮)**:仅 Dashboard 显示双 FAB `[+ 任务][+ 习惯]`;在二级页用顶部右侧 + 按钮

### 1.3 IA 选型理由

评估了三套方案,选择 **方案 B · 今日 Dashboard**:

| 方案 | 优点 | 缺点 |
|---|---|---|
| A · 双 Tab 平级 | 路径清晰 | 习惯打卡多一次跳转 |
| **B · 今日 Dashboard(已选)** | 一屏看完「要做 + 要打卡」,对齐 PRD O1 | 今日任务多时屏幕稍挤 |
| C · 单列+时间线 | 任务习惯混排效率高 | 违背 PRD 已定义的「今日视图」,屏幕不够 |

## 5. 数据模型 + Mock 数据

### 5.1 实体字段

```js
// Task —— 存储
{
  id: "t_001",
  title: "回复 X 项目邮件",       // 必填
  note: "把今天会议提到的几个点同步给客户",  // 可选
  dueAt: "2026-07-26T14:00:00+08:00",        // ISO+时区;无则 null
  priority: "P0",                            // P0|P1|P2|P3,默认 P3
  labels: ["工作", "沟通"],                  // ≤5
  status: "OPEN",                            // OPEN|DONE
  doneAt: null,                              // 完成时间
  // 注意:不设 parentId 字段(顶层 Task 永远是父,无业务意义;如未来支持多层子任务,再加)
  subtasks: [                                // 一层嵌套;建议 ≤7 个(超出禁用添加按钮)
    { id: "t_001_s1", parentTaskId: "t_001", title: "整理会议纪要", done: true },
    { id: "t_001_s2", parentTaskId: "t_001", title: "列出客户问题清单", done: false }
  ],
  createdAt: "2026-07-26T08:12:00+08:00",
  deletedAt: null                            // 软删除时间
}

// Habit —— 存储
{
  id: "h_001",
  title: "阅读 30 分钟",
  icon: "📖",
  frequency: "DAILY",                        // DAILY|WEEKLY
  targetPerPeriod: 1,                        // DAILY 固定 1;WEEKLY=次数
  createdAt: "2026-07-01T...",
  deletedAt: null
}

// CheckIn —— 存储
{
  id: "c_001",
  habitId: "h_001",
  checkInDate: "2026-07-26",                 // 自然日,按用户时区
  isBackfill: false,                         // 是否补卡
  createdAt: "2026-07-26T21:05:00+08:00"
}

// Streak —— 派生(不存,运行时按 CheckIn 计算)
{
  habitId: "h_001",

  todayChecked: true,
  thisWeekDone: 5, thisWeekTarget: 7
```

|---|---|---|---|
| Task | 12 条 | P0×2 / P1×3 / P2×4 / P3×3;有/无子任务;有/无标签;有/无截止;过期 1 条;已完成 3 条 | `t_001` (P0+子任务), `t_007` (DONE), `t_010` (已过期) |

### 5.3 交互触发的状态变化

| 触发 | 状态变化 | UI 反馈 |
|---|---|---|
| 点 TaskCard 勾选 | `status: OPEN→DONE`,`doneAt=now()` | 删除线 + 绿勾 + Toast「已完成 ✓」 |
| 点 HabitCard 打卡图标 | 写入 `CheckIn` | 按钮变「已打卡 ✓」+ StreakBadge 重算 + Toast「已打卡,连续 N 天 🔥」 |
| 点「补卡」日期 | 写入 `CheckIn(isBackfill=true)` | StreakBadge 重算 + Toast「已补卡,连续 N 天」 |
| 点 Dashboard「快进 X 天」 | 模拟时钟前进 | 看 streak 断签、回收站清理 Banner 出现 |
| 拖动看板卡片 | `status` 切换 | 同列表勾选效果 |

## 6. 8 个核心交互流

| # | 流程 | 步骤 | 反馈 |
|---|---|---|---|
| 1 | **新建任务** | 列表/详情 → 点 + → Sheet 滑入 → 标题(必填)→ 优先级(默认 P3)→ 截止(可选)→ 标签(**≤5,满 5 个时输入框置灰**)→ 保存 | Sheet 滑出 + 列表**按 §7.4 排序规则插入位置** + Toast「已保存 ✓」(30s 撤销) |
| 2 | **完成任务 / 重新打开** | 列表 → 点勾选 | OPEN↔DONE 双向:删除线+绿勾 / 删除线移除 + Toast「已完成 ✓」或「已重新打开」(30s 撤销) |
| 3 | **习惯打卡** | Dashboard/列表 → 点 HabitCard 图标 | 按钮变「已打卡 ✓」+ StreakBadge +1 + Toast「已打卡,连续 N 天 🔥」 |
| 4 | **习惯补卡** | 习惯详情 → 「补卡」 → Sheet(3 天日期可选,今天和未来置灰)→ 选日期 | StreakBadge 重算 + Toast「已补卡,连续 N 天」 |
| 5 | **回收站恢复** | 我 → 回收站 → 选条目 → 「恢复」 | 回到原列表,`deletedAt` 清空 |
| 6 | **删除任务** | 任务详情 → 「删除」 → 确认弹窗 → 软删除 | 列表移除 + Toast「已移入回收站」(30s 撤销) |
| 7 | **看板拖拽** | 列表 → 切看板 → 拖卡片到另一列 | `status` **OPEN↔DONE 双向切换** + Toast「已更新状态」;详见 §7.5 看板状态机 |
| 8 | **删除习惯** | 习惯详情 → 「删除」 → 确认弹窗 → 软删除 | `Habit.deletedAt = now()` + Toast「习惯已删除」(30s 撤销) |

## 7. 关键场景状态机

### 7.1 习惯打卡

```
(未打卡) todayChecked=false,按钮:打卡,提示:今天还没打卡
   │ 点图标
   ▼
(已打卡) todayChecked=true,按钮:已打卡 ✓,StreakBadge:N 天
   │ 跨日(快进演示)
   ▼
(新一天未打卡) todayChecked=false,StreakBadge:上次 N,提示:今天还没打卡
```

### 7.2 补卡窗口

```
今日(2026-07-26)
  ├─ 大前天(07-23):✓ 可补
  ├─ 前天(07-24):  ✓ 可补
  ├─ 昨天(07-25):  ✓ 可补
  ├─ 今天(07-26):  ✗ 置灰且不可点击(可见但禁用,今天不算补卡)
  └─ 大后天起(07-22 及更早): ✗ 置灰且不可点击(可见但禁用;PRD US-HABIT-01 AC-3 要求)
```

### 7.3 新建任务表单

```
默认:title="", priority=P3, dueAt=null, labels=[]
点保存:
  if title.trim()=="" → Toast「请输入任务标题」+ 字段红色描边
  else → 写入 tasks[],Sheet 关闭,Toast「已保存 ✓」(30s 撤销)
撤销 Toast → 从 tasks[] 移除该 id → 列表回到原状
```

### 7.4 任务排序规则(对齐 PRD US-TASK-02 AC-2)

> **设计选择**:采用主流 todo 产品惯例 —— **P0 最重要排前**。PRD 原文"P3 → P0 倒序"是中文表达歧义,本规范显式选定 P0 在前的语义,作为后续工程实现的不二依据。

```
排序键:
  PRIMARY: priority 降序(P0 → P3,P0 最重要排前)
  SECONDARY: dueAt 升序(无截止排最后,同截止按 createdAt 升序)
  TERTIARY: createdAt 升序(兜底)

列表插入:新任务按上述规则插入排序位置,而不是简单 unshift 到头部。
看板排序:列内自上而下按 priority → dueAt。
代码示例:`PRIORITIES.indexOf(a) - PRIORITIES.indexOf(b)`(<0 表示 a 排前)
```

### 7.5 任务勾选状态机(对齐 PRD TASK-004 双向)

```
(OPEN) status=OPEN, doneAt=null,无删除线,白底勾选框
   │ 点勾选
   ▼
(DONE) status=DONE, doneAt=now(),删除线,绿勾 ✓
   │ 再点勾选(列表 / 详情页均可触发)
   ▼
(OPEN) status=OPEN, doneAt=null,无删除线
```

### 7.6 看板拖拽状态机(对齐 PRD TASK-004)

```
(OPEN 列)
   │ 拖到「已完成」列
   ▼
(DONE 列) → 触发 §7.5 的 OPEN→DONE 状态切换 + Toast「已更新状态」

(DONE 列)
   │ 拖到「未完成」列
   ▼
(OPEN 列) → 触发 §7.5 的 DONE→OPEN 重新打开 + Toast「已重新打开」

注:看板拖拽不进入"30s 撤销"队列(用户主动拖拽是高确定性操作)。
```

## 8. 边缘 / 错误状态清单

| 场景 | UI 表现 |
|---|---|
| 今日无任务 | Dashboard 区块显示插画 + 「今天很轻松,要不要加一件事?」+ [+ 新建任务] CTA |
| 全部无任务 | 列表空状态:插画 + 「还没有任务,从现在开始」 |
| 看板 OPEN 列空 | 列内显示「拖拽任务到此」占位 |
| 搜索无结果 | 「无匹配任务,试试其他关键词」+ 「清除搜索」 |
| 回收站即将清理(≤3 天) | 顶部 Banner:橙色背景 + 图标 + 「X 条任务 2 天后将被清理」+ 「查看回收站」 |
| 习惯今天漏签 21:00 | Dashboard 顶部出现「📍 你今天有 N 个习惯还没打卡」+ 跳转链接 |
| 习惯 streak 断签 | HabitCard 显示「上次连续 N 天」+ 橙色提示 |
| 截止时间已过 | TaskCard 标题变红 + 「已过期」角标 |
| Push 通知降级 | 顶部铃铛红点 + 「通知中心」列表(展示 2-3 条模拟通知)。**文案规范见 §8.2** |

### 8.1 撤销机制统一规则

- **可撤销**:新建任务、完成任务 / 重新打开、删除任务、回收站永久删除、习惯补卡、删除习惯
- **撤销窗口**:30 秒(Toast 自动消失即不可撤销)
- **撤销实现**:从 `tasks[]` / `checkIns[]` / `habits[]` 移除对应 id,UI 立即回滚
- **不提供撤销**:看板拖拽切状态(用户主动拖拽是高确定性操作)、设置项修改

### 8.2 Push 通知文案规范(严格对齐 PRD US-TASK-04 AC-2)

| 触发 | 标题 | 正文 |
|---|---|---|
| 任务到期前 1 小时 | `⏰ 任务即将到期` | `{任务标题}`(PRD AC-2 仅要求显示任务标题) |
| 习惯当天漏签 21:00 | `📍 别忘了打卡` | `{习惯名}今天还没打卡` |
| 连续打卡里程碑(7/30/100 天) | `🔥 连续打卡 N 天` | `{习惯名} 已连续 N 天,继续加油!` |

**实现要求**:
- 标题 ≤16 字,正文 ≤48 字,过长截断加 `…`
- 点击通知跳转到对应任务详情 / 习惯详情
- iOS Safari 不支持 Web Push 时降级到「通知中心」列表(顶部铃铛红点 + Badge)
- PRD §8 风险 #3:**补卡限流**(同习惯每天 5 次补卡请求),触发时前端 Toast「操作太频繁,请稍后再试」(原型不模拟)
